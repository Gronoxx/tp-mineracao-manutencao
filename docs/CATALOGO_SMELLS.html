4. Caveats metodológicos

Atenção ao usar esses números:

  1. Quase tudo é Java. Transferência para Python perde ~5–10pp em F1 (literatura cross-language; Sandouka 2023; estudos de transfer learning).
  2. Números pré-2018 são suspeitos. Fontana 2016 (F1 0.96–0.99) foi sistematicamente deflacionado por Di Nucci 2018 e estudos subsequentes. Use só os números pós-2020.
  3. Cohen's kappa entre anotadores é 0.4–0.6 para smells subjetivos — esse é o teto absoluto que nenhuma técnica cruza.
  4. Cross-project é o teste real. Within-project F1 de 0.85 vira ~0.55–0.65 em cross-project. A maioria dos números acima é within-project.
  5. F1 ML do Fontana e descendentes diretos foram baseados em datasets balanceados 50/50. Em prevalência realista (~2–5%), a maioria desses números cai 20–40pp.

6. O que isso significa para o nosso projeto

Os 12 smells finais cobertos pela ferramenta estão organizados em três camadas, com workarounds opcionais sob decisão do trio:

6.1 Camada 1 — Regras estáticas core (5 smells)

  • Long Method Regras (evidência) — F1 0.84 cross-project (Beyazit 2026); gap de +3pp para ML não justifica complexidade
  • Long Parameter List Regras (evidência) — regras vencem ML por 6pp
  • Magic Numbers / Strings Regras (estrutural) — ruff PLR2004 + extensão AST
  • Deeply Nested Conditional Regras (estrutural) — pylint R1702
  • Dead Code intra-função Regras (estrutural) — pylint + vulture

6.2 Camada 2 — Regras estáticas adicionais (4 smells)

  • Refused Bequest Regras (evidência) — MRO traversal + override count, regras vencem ML por 7pp
  • Duplicate Code Tipo-1/2/3 Regras (evidência) — NiCad com suporte Python ou AST hash custom
  • Long Message Chain Regras (estrutural) — algoritmo PyExamine portado
  • Middle Man Regras (estrutural) — algoritmo PyExamine portado, intra-arquivo

6.3 Camada 3 — Detecção ML class-scope (3 smells)

Detecção via Qwen2.5-Coder-1.5B + LoRA classifier (mesmo modelo base dos LoRAs de refatoração):

  • Feature Envy ML modesto — gap +8pp; F1 esperado em Python ~0.65-0.80
  • God Class / Blob ML — gap +23-28pp; F1 esperado em Python ~0.70-0.85
  • Data Class ML — gap +11pp; F1 esperado em Python ~0.70-0.85

6.4 Camada 4 — Workarounds (decisão pendente do trio)

Smells antes "fora do escopo" agora viáveis com workarounds confirmados:

  • Type-4 semantic clones — UniXcoder zero-shot + GPTCloneBench Python pairs (~1-2 sem)
  • Shotgun Surgery — PyDriller + co-change heuristic, requer flag --repo-path (~2-3 sem)
  • Divergent Change — PyDriller + change-coupling, requer flag --repo-path (~2-3 sem)

O trio escolhe entre: apenas Type-4 (recomendado se priorizar diferenciador no paper); apenas history-based; ambos; ou nenhum (foco no polimento dos 12 base).

6.5 Refatoração via LoRA (7 smells)

Geração automática de refatoração apenas para um subset dos 12 detectados — outros smells são detecção apenas, com sugestão textual/manual:

  • R1 Long Method → Extract Method
  • R2 Long Parameter List → Introduce Parameter Object
  • R3 Magic Numbers → Replace with Named Constant
  • R4 Deeply Nested → Guard Clauses
  • R5 Dead Code → Remove
  • R6 Feature Envy → Move Method
  • R7 God Class → Extract Class

Stack unificado: Qwen2.5-Coder-1.5B é o único modelo base carregado em memória. 11 LoRAs são swapados conforme tarefa: 7 LoRAs de refatoração + 3 LoRAs de classificação class-scope + 1 LoRA classifier de Long Method (apenas para ablação experimental no paper, comparando regras vs. ML). Treino reusa pipeline única de mineração via PyDriller.

6.3 Smells deliberadamente fora do escopo

Apesar de gap ML real, ficam fora por restrições arquiteturais ou de dataset:

  • Type-4 semantic clones — gap ML enorme, mas exige escopo multi-função e BigCloneBench é Java-only
  • Shotgun Surgery / Divergent Change — gap ML grande, mas requer histórico de commits (fora de "arquivo enviado para CLI")
  • Data Class — gap ML real, mas é class-scope; God Class já cobre a categoria class-scope com escopo de prazo limitado

6.4 Smells deliberadamente evitados

  • Refused Bequest — regras vencem, ML perde
  • Bad Naming, Comments smell, Speculative Generality — ground truth fundamentalmente ruidoso (kappa baixo); pouca esperança de que qualquer técnica converja
  • Inappropriate Intimacy — pylint W0212 já cobre o caso prático; literatura ML insuficiente

Linha defensável no paper: "Selecionamos a cobertura per-smell minimizando complexidade arquitetural enquanto respeitamos a evidência empírica acumulada na literatura — ML onde Liu (2018), Kovačević (2022) e Beyazit (2026) mostram gap consistente; regras onde Beyazit (2026) e Di Nucci (2018) mostram equivalência ou superioridade."
